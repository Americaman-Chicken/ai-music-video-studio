# AI Music Video Studio 3.6

楽曲、歌詞、イラストからミュージックビデオを作る日本語 PWA です。Android Chrome を主対象とし、素材の編集、分析、保存、書き出しは端末内で行います。API キーや有料サービスは不要です。

## Android にインストール

1. HTTPS の GitHub Pages URL を Android Chrome で開きます。
2. アプリ内の「アプリをインストール」または Chrome メニューの「アプリをインストール」「ホーム画面に追加」を選びます。
3. 更新が公開されたら「更新を確認」を押します。作業を保存し、アプリのウィンドウと同じサイトのタブを閉じてから開き直します。

初回起動には通信が必要です。初回起動後はアプリ本体と手動制作をオフラインで使えます。AI 機能を使う場合は、最初に公開モデルや実行ライブラリを取得します。キャッシュが消去された場合は再取得が必要です。

## 制作の流れ

1. 曲名、音源、画像、歌詞を入力します。ファイル形式は端末のブラウザがデコードできるものを選びます。画像は選択順に番号が付きます。
2. 「BPM・拍・反復構造を解析」を押します。BPM や区間名は手動で修正できます。構成は音響特徴・反復・同期済みの歌詞から求めた候補です。
3. 「音源から字幕を作る」を押すと、先に音声認識して時刻付き字幕を作ります。歌詞が入力済みなら、その字幕と歌詞を照合して修正候補を出します。後から歌詞を入力・修正したときは「入力した歌詞で字幕を再照合」でモデルを再実行せず照合できます。元の認識字幕は残り、SRT で保存できます。歌詞欄が空なら「認識字幕を同期候補にする」で元字幕を候補にできます。歌唱範囲を変更した場合は、現在の範囲にある既存字幕を使います。「歌い出し」に秒数を入れるとそれ以前を除外し、「間奏・アウトロ」に `32.5-47.2` のように複数区間を行ごとに指定できます。指定した区間は認識と表示から外れます。候補が未適用の間は、AI 同期モードで歌詞を仮表示しません。「均等配置」は仮の時刻を使います。提示された歌詞と時刻を確認して「同期候補を適用」します。空欄がある場合は「時刻のある行を適用」で先に反映できます。残りの行は歌詞欄に残り、秒数の入力や「再生位置を入れる」で補えます。数字は入力歌詞と認識結果の一致率です。「この時刻を試聴」で開始位置の少し前から聞き、必要なら秒数を直します。Tiny で候補が不足する場合は、端末の容量と処理負荷が増える Base を選んで再試行できます。単語にはモデルの認識時刻を使い、文字の時刻は単語時刻から推定します。歌い方や伴奏、漢字とかなの表記差によってずれる場合は、タイムラインで時刻を直すか、タップ同期・手動 LRC・均等仮配置を使います。
4. 「文字演出」で自動切り替え、ポスター・ビート、縦組み、円弧、分割レイアウト、字幕を選べます。自動では歌詞の行が変わるたびにレイアウトを切り替えます。字幕以外の演出では KanjiVG の筆順データを使い、筆圧をつけた輪郭を一画ずつ描きます。筆順データのない文字は端末のフォントで補います。演出指示を入力して「演出プランを作成・更新」を押します。自由文を LLM で解釈する場合は、演出エンジンで「端末内 LLM」を選びます。WebGPU やモデルが利用できない場合は、画面に理由を表示してルール解析に切り替えます。ルール解析では、例えば次の指示が使えます。

   ```text
   白黒、フェード
   10-20秒: 画像2 ズームイン
   サビ: 揺れ、中央
   ```

5. プレビュー下の時間軸から拍・構成・歌詞・演出を確認します。演出区間を押すと開始と終了、画像、カメラ、文字アニメーション、区間の文字演出を編集できます。出力区間に開始と終了を入力し「出力区間の演出だけ更新」を押すと、指定範囲内のプランだけが更新されます。部分動画の出力も同じ範囲設定を使います。
6. 「端末にプロジェクト保存」を押します。「新規プロジェクト」で別の曲を作成し、一覧で保存した曲を選んで開けます。v3.1 の保存データは同じサイトのオリジン上で初回に移行されます。端末のサイトデータ削除や容量回収に備え、素材 ZIP も別途保管してください。
7. 縦横比、解像度、形式を指定し「端末内で動画を書き出す」を押します。負荷が高い場合は 480p または 720p を選びます。書き出し中はアプリを前面に保ちます。MP4 はブラウザが H.264/AAC 録画に対応する場合に利用できます。非対応の端末では WebM を選んでください。対応端末では WebCodecs で時刻を固定して書き出します。端末によっては実時間録画になり、負荷によって尺やフレームレートが変動する場合があります。

## 1枚絵と歌詞を重ねたレイヤー演出

1. 音源、背景にするイラスト、同期済みの歌詞を入れます。人物を分けたい場合は、背景の後に透過 PNG または緑背景の人物画像を選択し、「前景レイヤー」で重ね方を指定します。
2. 「レイヤー演出」で巨大文字の切り抜き、タイル分解、波のゆがみ、横ずれグリッチを選びます。「4拍ごとに切り替え」を選ぶと通常、タイル、巨大文字、横ずれの順に切り替わります。巨大文字はその時に表示される歌詞から選びます。
3. 「プレビューするレイヤー」で絵と前景、歌詞、合成映像を切り替えます。書き出しは常に合成映像です。区間を指定する場合は演出指示に `8-12秒: 巨大文字で切り抜く` のように書き、演出プランを作成します。
4. 書き出し後に、描画した連続フレームから検出した大きな明暗反転の回数を参考値として表示します。

## WebM を PC で MP4 に変換

アプリで保存した WebM は、Python と libx264 対応の FFmpeg を使って PC 上で H.264/AAC の MP4 に変換できます。出力先には新しいファイル名を指定します。

    python convert_mp4.py input.webm output.mp4

## 素材と通信

制作素材とプロジェクトはブラウザ内のメモリまたは IndexedDB に保存されます。モデル取得に使う CDN とモデル配布元へ、音源・画像・歌詞・演出指示を送信する処理はありません。モデルを使わない手動制作では外部ライブラリや重みを取得しません。素材 ZIP、制作途中のファイル、API キーを GitHub に登録しないでください。

旧 Whisper JSON / LRC の読み込みと、ローカル PC 向けの Python と Remotion の処理も残しています。素材 ZIP をローカルの `public/` に展開し、Python 3.11 で `faster-whisper==1.1.1` を導入して `python align.py` を実行すると、`out/` に時刻データが作られます。`npm install` と `npm run render` では PC 上で従来形式の MP4 を生成できます。旧 Remotion の映像は端末プレビューと異なります。同梱の旧 Render MV Actions は、公開可能なテスト素材を置いた非公開リポジトリ向けです。

## GitHub Pages への公開

1. GitHub に公開用リポジトリを作成し、ソースの `main` を push します。
2. Settings → Pages → Build and deployment の Source を **GitHub Actions** に設定します。
3. Actions → **Publish app** → **Run workflow** を実行します。テストに合格すると `app/` のみが配信されます。実行結果に表示された URL を開きます。
4. `app/`、テスト、公開ワークフローへの変更を `main` に push すると再検証・公開されます。公開ビルドはコミットごとに Service Worker のキャッシュ名を切り替えます。

## 開発とテスト

```sh
python -m http.server 8000 --bind 127.0.0.1
# http://localhost:8000/app/
node tests/core.test.cjs
python -m unittest discover -s tests
python -m pip install playwright pillow
python -m playwright install chromium
python tests/browser_smoke.py
```

ブラウザテストには FFmpeg と ffprobe が必要です。3 分の音源を書き出す確認を追加する場合は `MV_LONG_TEST=1` を指定します。システム Chromium を使用する場合は `CHROMIUM_PATH=/usr/bin/chromium` を指定できます。実測値、対応状況、次に着手する項目は [DEVELOPMENT.md](DEVELOPMENT.md) に記録しています。

実 Whisper で合成日本語音声の行開始誤差を測るには、追加で pyopenjtalk-plus==0.4.1.post10 をインストールし、以下を実行します。測定用の音声はその場で生成します。

    python tests/recognition_benchmark.py --model tiny
    python tests/recognition_benchmark.py --model base
